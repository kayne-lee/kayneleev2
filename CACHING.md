# Why `vercel.json` exists

Vite content-hashes everything it emits into `dist/assets/` — JS, CSS and the
WebP images generated by `vite-imagetools`. A changed file always gets a new
filename, so those URLs can never serve stale content and are safe to cache
for a year (`immutable`).

Before this file existed, Vercel's zero-config Vite preset served them as
`public, max-age=0, must-revalidate`, meaning every repeat visit paid a
revalidation round trip for every asset.

`index.html` is the pointer to the current hashes, so it stays uncached.

## The rewrite is load-bearing

Defining `vercel.json` replaces the preset's implicit SPA fallback. Without the
`rewrites` entry, any path other than `/` 404s instead of reaching the `*` route
in `src/App.tsx`. Vercel applies rewrites only after the filesystem check, so
real static files still win over the fallback.

Images must stay in `src/assets/img/` (imported, hashed) rather than `public/`
(copied verbatim, unhashed) for the immutable policy to apply to them.
